FINAL FIGMA PROMPT — PERSONAL GRAPHIC DESIGN PORTFOLIO

Create a complete personal graphic design portfolio website for my university/Erasmus application.

This is not a commercial freelance portfolio and should not feel like a generic “designer for hire” website. It should feel personal, artistic, editorial, experimental, visually intentional, and strongly connected to my identity as a graphic design student.

The website should present my work as a visual experience, not simply as a collection of project thumbnails.

I will provide:

1. A Notion database containing the factual/content information for my projects.
2. Actual files for the projects, including images, PDFs, videos, screenshots, process material, mockups, etc.
3. A visual-reference PDF/file showing the kind of visual language, composition, interaction, typography, and atmosphere I am interested in.
4. A Representation field/tab in Notion for each project. This contains my specific instructions for how I want that project to be visually represented.

Use all of these sources together.

⸻

1. SOURCE OF TRUTH / PRIORITIES

Treat the provided materials as follows:

A. Representation instructions — project-specific art direction

The Representation field in Notion is extremely important.

It is not passive metadata and it should not simply be displayed as text on the website.

It contains my instructions about how I imagine each project should look, feel, behave, and be structured visually.

For every project:

* Read the Representation instructions carefully.
* Translate them into actual layout, composition, sequencing, scale, spacing, image/video treatment, typography placement, interaction, and visual rhythm.
* Follow the intended visual concept of the Representation instructions.
* Use the Representation instructions to determine how that particular project should unfold on the page.
* Do not replace these instructions with a generic portfolio template.
* Do not make every project look identical simply for the sake of consistency.

If the Representation instructions say that a project should begin with a video, begin with the video.

If they indicate a specific image should dominate the screen, give it the appropriate scale.

If they describe overlapping images, unusual positioning, a particular sequence, large typography, process material, screenshots, or another visual treatment, interpret that as actual art direction and implement it.

B. Actual project files — visual source

Use the actual project files I provide as the primary visual material.

Do not invent generic images, stock imagery, placeholder projects, or unrelated visuals when actual project material is available.

Preserve the character of the original work.

Crop, scale, position, sequence, overlap, animate, or otherwise present the material according to the Representation instructions and overall design system.

C. Notion project information — factual/content source

Use the Notion database as the source of truth for factual information such as:

* Project name
* Category
* Year/date
* My role
* Whether it was a team project
* Team members
* Student numbers, if provided
* Tools/apps used
* Short description
* Concept/problem
* Portfolio reason
* Links
* Other project-specific information

Do not invent factual information that is not provided.

D. Visual-reference PDF/file — overall visual direction

Use the reference PDF/file to understand:

* visual atmosphere
* typography
* composition
* interaction
* editorial feeling
* use of negative space
* image/video treatment
* pacing
* transitions
* navigation ideas
* visual hierarchy

Use it as inspiration and design direction, not something to copy literally.

The final website should feel original and personal.

Overall priority

When making decisions, use this hierarchy:

1. Project-specific Representation instructions
2. Actual project files
3. Notion factual/content information
4. Overall portfolio design system and visual reference

The goal is to combine these rather than letting one erase the others.

⸻

The website should feel:

* personal

* editorial
* artistic
* graphic-design-driven
* experimental but controlled

* a standard Behance-style grid
* a corporate agency website
* a basic student portfolio template
* a collection of identical cards
* excessive UI elements
* unnecessary decoration

The design itself should demonstrate that I understand:

* typography

* hierarchy

* image-making
* visual storytelling
* sequencing
* art direction
* interaction
* visual identity

The portfolio should feel like my work is creating the website, rather than the website simply containing my work.

The main experience should be a continuous scrolling homepage.

The visitor should be able to scroll through the portfolio almost like moving through a visual publication or exhibition.

The main structure should be:

1. Introduction / opening
2. Project 01
3. Project 02
4. Project 03
5. Project 04
6. Project 05
7. Project 06
8. Project 07
9. Project 08
10. Project 09
11. About / Profile
12. Ending / closing

Do not make the projects feel like nine separate website pages unless the Representation instructions for a specific project strongly suggest otherwise.

They should primarily feel like nine chapters within one continuous experience.

⸻

4. OPENING / INTRODUCTION

Create a strong opening screen.

The first screen should introduce me immediately but without feeling like a conventional résumé.

Potential content:

* My portrait/photo, using the actual image I provide
* My name
* “Graphic Designer” / “Graphic Design Student”
* University information if provided
* A short personal statement
* A subtle indication that the visitor can scroll
* Access to the Contents navigation

The opening should feel visually confident and editorial.

Do not overload it with information.

The first screen should establish the visual language of the entire portfolio.

⸻

Instead, create a Contents control that can open an overlay/menu.

The Contents overlay should provide navigation to:

* Introduction
* Project 01
* Project 02
* Project 03
* Project 04
* Project 05
* Project 06
* Project 07

* About

The Contents interaction should feel integrated with the editorial character of the website.

When a project is selected, navigate smoothly to that section.

The Contents system should work on both desktop and mobile.

⸻

6. PROJECT PRESENTATION

Each project should be treated as a visual chapter, not a standard portfolio card.

Do NOT force every project into:

image → title → description → gallery

Instead, allow each project to have its own structure based on its Representation instructions.

For example, one project might begin with:

* a full-screen video

Another might begin with:

* a huge image
* minimal typography
* then gradually reveal information

Another might begin with:

* a composition of multiple images
* title integrated into the composition

Another might emphasize:

* process
* sketches
* typography
* screenshots
* physical documentation
* editorial spreads

The overall website must remain coherent, but the internal visual language of each project can vary.

This variation is intentional.

⸻

7. PROJECT OPENING / HERO

Every project should have a strong opening moment.

Use the Representation instructions to determine what this should be.

Possible treatments include:

* full-screen video
* almost full-screen video
* large image
* image sequence
* typography-led opening
* image + title composition
* collage
* editorial spread
* unusual image positioning
* immersive visual sequence

Do not automatically put the project title at the top.

The title placement should be determined by the project’s visual concept.

⸻

8. VIDEO PROJECTS

For projects containing video, video can be a major part of the project experience.

If the Representation instructions indicate that the video should come first:

* make it full-screen or almost full-screen
* allow it to become the dominant first impression
* avoid placing unnecessary UI over it
* use appropriate autoplay/muted behavior where technically appropriate
* make controls subtle
* preserve the visual quality and aspect ratio of the original material

After the video, reveal the project information naturally.

Possible sequence:

Video → Project title → Category/year → Description → Role/tools/team → Concept/problem → Supporting material → Full project links

But this is only a starting structure.

The Representation instructions should override this sequence when they describe another approach.

Process should be included when it adds meaning.

Do not treat process images as secondary filler.

If a project’s Representation instructions emphasize process, make it an important part of the visual narrative.

Possible presentation:

* chronological sequence
* scattered editorial arrangement
* large process image followed by explanation
* sketches next to final work
* small images surrounding a main artifact
* visual archive
* annotated material

The process should help communicate how I think and design.

include these links in an elegant editorial way.

13. PROJECT TRANSITIONS

The transitions between projects should feel intentional.

The visitor should understand when one project ends and another begins, but the experience should remain continuous.

Possible transitions:

* typography
* large project numbers
* negative space
* changing image scale
* subtle shifts in layout
* transitional text
* a visual pause
* a change in background treatment where appropriate

Avoid excessive animation.

The transition should support the work rather than compete with it.

Use clear project numbering:

01 / Project Name
02 / Project Name
03 / Project Name

etc.

The numbering can become part of the visual identity of the website.

Use it consistently while allowing its placement and scale to change according to each project’s Representation instructions.

15. GLOBAL DESIGN SYSTEM

Create a coherent visual system across the whole website.

The system should define:

Typography

Use typography as one of the primary design elements.

Establish:

* display typography
* body typography
* metadata typography
* project numbering
* navigation typography
* link styling

The typography can sometimes be experimental:

* large scale
* unusual alignment
* vertical placement
* edge positioning
* interaction with images

But readability must remain intentional.

Spacing

Create a strong spacing system.

Use:

* generous negative space where appropriate
* tighter information groupings where appropriate
* consistent margins
* clear rhythm

Grid

Establish an underlying grid but do not make every project visibly obey the same rigid layout.

The grid should provide structure while allowing art direction to break or reinterpret it.

Color

Create a restrained global palette based on the visual reference and actual project material.

Do not impose a single color treatment over projects if doing so damages the original work.

Metadata

Create a consistent language for:

* year
* category
* role
* tools
* team
* project number

Links

Create a consistent visual treatment for external links and PDFs.

Navigation

Create consistent behavior for Contents, scrolling, back-to-top, and project transitions.

⸻

16. CONSISTENCY VS. VARIATION

This is extremely important.

The website should feel like one portfolio, but the nine projects should NOT look like nine copies of the same component.

Think of it as:

Global system = consistency

Representation = project-specific art direction

Therefore:

* typography can remain related
* spacing can remain related
* navigation can remain related
* numbering can remain related
* metadata can remain related

while:

* image scale can change
* composition can change
* sequencing can change
* project openings can change
* video treatment can change
* text placement can change
* image arrangements can change
* process presentation can change
* visual rhythm can change

Do not normalize all projects into one generic template.

Use motion thoughtfully.

Possible interactions:

* smooth scrolling
* subtle image reveals
* hover states
* typography movement
* project transitions
* video transitions

Design the experience for both desktop and mobile.

The mobile version should not simply be a collapsed desktop version.

Adapt:

* typography
* image scale
* project sequencing
* navigation
* video dimensions
* spacing
* metadata
* Contents overlay
* interactive elements

Although the website is experimental, it should still be usable.

* readable text
* clear hierarchy
* sufficient contrast
* understandable navigation
* obvious interactive elements

* accessible external links
* appropriate alt text where applicable
* mobile usability

* project names

* tools

23. DO NOT OVERRIDE THE REPRESENTATION FIELD

The Representation field is a direct instruction from me about the intended visual presentation of each project.

Do not reduce it to a small text description.

For every project, ask internally:

What is this project’s intended visual experience?

Then build the section around that answer.

If Representation says:

* video first → video first
* image dominant → image dominant
* process-focused → process-focused
* unusual composition → preserve the unusual composition
* minimal typography → keep it minimal
* image sequence → respect the sequence
* specific visual rhythm → reproduce that rhythm
* specific interaction → implement it where technically possible

Do not “clean up” an intentionally unusual design into a generic portfolio layout.

⸻

24. CONTENT HIERARCHY

The website should have several levels of information:

Level 1 — Visual impact

The main artwork, image, video, or composition.

Level 2 — Project identity

Project number, title, category, year.

Level 3 — Context

Description, concept, problem, role, tools, team.

Level 4 — Supporting material

Process, experiments, documentation, secondary imagery.

Level 5 — Further information

PDFs, websites, external links, additional documentation.

Not every project needs all five levels in the same order.

Use the Representation instructions to determine the hierarchy for each individual project.

⸻

25. OVERALL EXPERIENCE

The visitor should feel as if they are moving through my graphic design practice.

The website should communicate not only:

“Here are my projects.”

but also:

“This is how I think, compose, experiment, and communicate visually.”

The portfolio itself should therefore be considered part of my design work.

The interface, typography, navigation, sequencing, motion, image treatment, and project presentation should all demonstrate graphic-design thinking.

⸻

26. FINAL DESIGN PRINCIPLE

The most important principle is:

Make the portfolio feel authored, not templated.

Use the provided visual reference to establish the overall atmosphere.

Use the actual project files to establish the visual content.

Use the Notion database to establish the factual information.

Use the Representation field to establish the individual art direction of every project.

Then build a single coherent visual system that connects everything together.

The final result should feel like a personal visual publication / digital exhibition of my graphic design work, with nine distinct projects presented as carefully art-directed chapters.

Do not make it look like a standard student portfolio.

Do not make all projects identical.

Do not prioritize generic UI conventions over the visual concept.

Let the work, typography, composition, sequencing, and Representation instructions drive the experience.
